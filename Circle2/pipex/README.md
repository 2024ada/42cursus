# pipex

**파일과 여러 명령의 입출력을 프로세스로 연결하기**

![C](https://img.shields.io/badge/C-334155?style=flat-square&logo=c&logoColor=white)
![Processes](https://img.shields.io/badge/Processes-0F766E?style=flat-square)

`pipe` · `fork` · `dup2` · `execve` · `waitpid`

## 무엇을 만들었는가

여러 명령을 자식 프로세스로 실행하고, 앞 명령의 표준 출력을 다음 명령의 표준 입력으로 전달하는 프로그램입니다. 셸의 파이프라인을 구성하는 운영체제 호출과 파일 디스크립터의 흐름을 직접 다룹니다.

**사용 기술:** C, Unix 프로세스·파일 API, 환경변수 `PATH`, 직접 구현한 Libft·get_next_line.

## 과제에서 요구한 범위

[Subject v3.2](en.subject.md)의 필수 실행 형태는 `infile cmd1 cmd2 outfile`입니다.

| 구분 | 명세의 요구사항 |
| :--- | :--- |
| 필수 | 두 명령의 파이프 연결, 입력·출력 파일 처리, 셸과 유사한 오류 처리 |
| 보너스 | 여러 명령 연결, `here_doc` 입력과 출력 파일 추가 쓰기(`>>`) |

여러 파이프와 `here_doc`은 지정된 보너스입니다. 현재 코드에는 마지막 인자에 따라 출력 파일을 생략하는 실행 경로도 있습니다. 이 차이는 아래 사용 규칙에 적었습니다.

## 실행 흐름

```mermaid
flowchart LR
    I["입력 파일 또는 here_doc"] --> A["명령 1<br/>자식 프로세스"]
    A -->|"pipe"| B["명령 2<br/>자식 프로세스"]
    B -->|"pipe"| C["추가 명령"]
    C --> O["출력 파일 또는 표준 출력"]
```

각 자식은 `dup2`로 표준 입출력을 연결하고 `execve`로 명령을 실행합니다. 부모는 자식의 종료를 기다리며 마지막 명령의 종료 상태를 반영합니다.

## 구현에서 주목할 부분

| 구현 | 처리 방식 | 코드 |
| :--- | :--- | :--- |
| 여러 명령 연결 | 이전 파이프의 읽기 FD를 다음 명령에 전달 | [`run_pid.c`](run_pid.c) |
| 실행 파일 탐색 | `PATH`를 분리하고 실행 가능 여부 확인, `/` 포함 경로 처리 | [`get_cmd.c`](get_cmd.c) |
| 입력·출력 준비 | 파일 열기, here_doc 수집, 일반 출력·추가 쓰기 모드 구분 | [`set_file.c`](set_file.c) |
| 명령 인자 분리 | 따옴표 구간을 고려하는 전용 문자열 분리 | [`cut_cmd.c`](cut_cmd.c) |
| 종료 상태 처리 | `waitpid`, `WIFEXITED`, `WEXITSTATUS`로 마지막 명령 결과 확인 | [`run_pid.c`](run_pid.c) |

파이프 연결은 명령 개수에 따라 반복해서 구성합니다. 출력 대상을 여는 부분과 명령 실행 부분을 분리해, 파일 처리와 프로세스 실행의 역할을 나누었습니다.

## 빌드와 실행

```sh
make
```

아래 예제는 이 디렉터리를 기준으로 실행합니다.

```sh
printf 'alpha\nbeta\nalpha\n' > input.txt

# 두 명령 연결
./pipex input.txt "grep alpha" "wc -l" result.txt

# 세 명령 연결
./pipex input.txt "grep alpha" "sort" "uniq" result.txt

cat result.txt
```

here_doc 입력:

```sh
./pipex here_doc END "cat" "wc -l" result.txt
```

실행 후 내용을 입력하고 별도 줄에 `END`를 입력하면 수집을 마칩니다. here_doc 모드에서는 출력 파일을 추가 쓰기(`O_APPEND`)로 엽니다.

`make bonus`는 기본 빌드와 같습니다. `make clean`, `make fclean`, `make re`도 지원합니다.

## 명세와 다른 출력 방식

명세에서는 마지막 인자를 출력 파일로 지정합니다. 현재 [`set_file.c`](set_file.c)는 마지막 인자를 명령처럼 분리한 뒤, 첫 단어를 [`get_cmd.c`](get_cmd.c)로 탐색합니다. `PATH` 탐색 또는 직접 지정한 경로에서 실행 가능한 파일을 찾으면 마지막 인자도 명령으로 실행하고 결과를 표준 출력으로 보냅니다.

```sh
# 마지막 인자인 "wc -l"도 명령으로 실행하고 결과를 터미널에 출력
./pipex input.txt "grep alpha" "wc -l"
```

충분한 인자가 있고 마지막 인자가 명령으로 탐색되지 않으면 출력 파일로 처리합니다. 출력 파일명이 실행 가능한 명령 이름과 겹치면 해석이 달라지므로 이 규칙을 고려해 이름을 지정해야 합니다.

명령 인자 분리는 이 프로젝트의 전용 구현이며 셸 문법 전체를 해석하지는 않습니다. here_doc은 소비 프로세스를 생성하기 전에 파이프에 입력을 기록하므로, 큰 입력은 파이프 용량에 따른 대기 동작을 추가 검증할 항목입니다.

### 평가자 `m**`

먼저 평가지에 있는 요소가 다 부합하는지 확인하고 코드 리뷰 진행했습니다. pipex과제를 수행하지 않아서 pipex가 어떤 것을 요구하는 프로그램인지에 대해 설명해주시고 shell에서 pipe가 어떤 식으로 작동하는지, 그리고 본인의 프로그램이 shell과 동일하게 작동하는지 꼼꼼하게 보여주셔서 평가요소에 있는 부분들은 전부 ok드렸습니다. shell에서 쓰이는 명령어를 어떻게 프로그램에서 구현하는지가 궁금했는데 환경변수에서 명령어가 있는지 확인하고 가져와서 사용할 수 있는 함수가 있다는 것을 자세하게 알려주셨고, shell과 동일한 출력을 하기위해 언어설정에 대해서도 꼼꼼하게 공부하신 것이 인상깊었습니다. 그 전에 평가했던 pipex는 완벽하게 이해하는데에 한계가 있었지만, 오늘 평가에서 피평가자분께서 코드 일반화를 통해 여러 상황에서도 동일하게 작동할 수 있는 로직으로 만드신 것을 보고 pipex가 작동하는 원리를 구조적으로 이해할 수 있어서 너무 좋은 평가시간이었습니다. 코드 만드시느라 수고 많으셨습니다!
